Selected work

Secure banking API

A personal project with public code: a Spring Boot REST API where customers sign up, log in, and move money between accounts. Every customer can reach only their own account, and the rule is enforced where it cannot be bypassed.

Java 17, Spring Boot 3, Spring Security, JWT, Spring Data JPA, Maven, Docker, GitHub Actions

View the code on GitHub

Sign-up and login
Passwords are hashed with BCrypt. Login returns a signed JWT, and an unknown email gets the same error as a wrong password.
Ownership in the service layer
The service checks who is calling before it reads or changes an account. A transfer must come from your own account, and a stranger cannot use the response to probe account numbers.
Money moves safely
Credit, debit and transfer run in transactions with row locking, so two requests at the same moment cannot overwrite each other's balance.
Tested and automated
More than 80 unit, controller and integration tests run on every pull request in CI. They cover forged and expired tokens, cross-account access and concurrent credits.

How I build

Check access where it can't be skipped

The service layer decides who can touch an account, so a new endpoint or a different front end cannot get around the rule.

Treat money as a transaction

A transfer either completes fully or changes nothing. Rows are locked in a fixed order, so opposite transfers cannot deadlock.

Make failures specific

Each error returns the right HTTP status and the same JSON shape, so a client always knows what went wrong and what to fix.

Prove it with tests

My tests try to break the rules: forged tokens, expired tokens, one customer attacking another's account, and fifty credits at once.
